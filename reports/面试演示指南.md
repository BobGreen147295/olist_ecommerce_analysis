## 演示方案 A：CLI Agent（最稳，推荐首选）

### Step 1（30秒）：一句话介绍

> "这是一个基于 LangGraph + 本地 LLM 的电商运营 Agent。你不需要写 SQL 或看报表，用自然语言问它就行。"

### Step 2（1分钟）：跑第一条命令

```bash
cd D:\olist_project
PYTHONIOENCODING=utf-8 .venv\Scripts\python src\agent\run_agent.py "分析客户分群情况，高价值客户和低价值客户分别怎么运营"
```

等 15-30 秒出结果，指着输出讲三件事：
1. "这里它自动调了 `query_user_segments` 和 `query_rfm_summary` 两个工具"
2. "分析部分，每条发现都引用了真实数据"
3. "策略部分，P0-P2 分级，每个策略有具体金额、渠道、时间"

### Step 3（1分钟）：再跑一个不同类型的问题

```bash
PYTHONIOENCODING=utf-8 .venv\Scripts\python src\agent\run_agent.py "支付方式分布有没有问题，怎么优化"
```

这次 Agent 会调 `query_payment_distribution`，展示它能根据问题类型自动选择不同工具。

### Step 4（30秒）：如果面试官问"和 ChatGPT 有什么区别"

> "ChatGPT 是通用对话，这个 Agent 背后接了真实数据——7 个 Pandas 查询工具，查出来的数字 100% 准确。LLM 只负责分析数据和生成策略，不碰原始数据。这就是混合 AI 架构。"

## 面试官大概率会问的三个问题

### Q1：LLM 选错了工具怎么办？

> "我有两层防护。第一，System Prompt 给每个工具配了选择规则——比如用户提到'趋势'就选 query_sales_trend。第二，即使选错了，工具返回的数据也是真实的，LLM 看到数据后发现和自己预期不符，会在分析中诚实说明'数据不足'——你刚才看到的第一个查询就是例子。"

### Q2：如果有 100 个工具，Agent 怎么选？

> "现在的 6 个工具是简单枚举。扩展方案是语义路由——把每个工具的 description 做 Embedding，用户问题也做 Embedding，选余弦相似度最高的 Top-K 个工具。这在技术上是成熟的方案，LangChain 和 LlamaIndex 都有现成实现。"

### Q3：这个系统能投入生产吗？

> "目前是 MVP 级别，演示了核心链路。要投入生产需要补充三件事：一是接入真实数据库而非 CSV，二是加权限控制和审计日志，三是做 MCP 标准化让其他 Agent 也能调用这些数据工具。这些在 README 的扩展方向里都已经规划了。"

## 演示时的雷区（千万别踩）

| 不要 | 正确做法 |
|------|---------|
| 说"这个项目很简单" | 说"核心链路跑通了，扩展方向已规划" |
| 主动提 XGBoost 标签是代理标签 | 被问到时诚实说明，同时强调"生产数据接入后流程不变" |
| 一次跑太多命令 | 最多 2-3 条，留时间给面试官提问 |
| 只说技术不说业务 | "这个 Agent 帮运营经理省了写 SQL 的时间" > "我用了 LangGraph" |
| 演示完就停住 | 主动问"你想看看某个具体模块的代码吗？"把主动权抛回去 |

## 如果全崩了的保底方案

打开项目 README，指着 Mermaid 架构图 + 代码结构讲：

> "这个项目最核心的不是能跑的 Demo，而是这套架构设计——混合 AI 三层架构，LLM 不碰数据，确定性工具打底。面试时间有限，我可以重点讲一下架构决策和模块拆分思路。"

然后讲：
1. 为什么拆 8 个模块而不是 1 个 God Script
2. 为什么 LLM 只做推理不碰数据
3. Agent 的三节点为什么是 fetch → analyze → recommend
