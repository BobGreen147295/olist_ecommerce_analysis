# 商家经营复盘与跨境研究整合

2026-10-21。本机账户体验已接通；GitHub 分支同步不等于生产发布。既有 Cloudflare/Render 地址、Shopify OAuth 回调和订单数据库保持不变。

## 使用路径

商家网站新增 `/reviews`，导航「经营复盘」。先在 `/data` 用原商家账户登录，再核对订单、保存复盘、主动请求 AI 解读、采纳一项检查并回填/导出。研究站提供公开资料与 AI 任务能力，RevenueOps 验证商家身份并读取该账户的汇总。本站原有营销任务和实验观察门禁继续独立工作，采纳复盘检查不会创建或执行营销活动。

公开研究站首页的主要入口指向既有 RevenueOps 网站；商家网站配置 `NEXT_PUBLIC_RESEARCH_SITE_URL` 后显示「研究资讯」。研究站尚未部署公网时不要填写本机 URL 到生产构建。正式域名及统一品牌迁移留待部署阶段。

## 服务边界

```text
商家浏览器 ──原 Bearer 会话──> RevenueOps /v1/commerce
  └─ 服务器验证账户并读取最小汇总
      └─ HTTPS + 独立服务密钥 + 不含用户名的账户作用域
          └─ 研究 API /api/internal/research/commerce
              └─ 按账户保存快照、解读任务、采纳检查和人工观察
                  └─ 原研究 Worker / 预算 / 付费回执
```

订单和 Shopify 凭据仍由 RevenueOps 保存，不互查数据库。研究服务保存复盘所需的派生汇总与人工输入，不接收订单明细、客户身份、商家登录令牌或 Shopify token。模型继续仅由研究 Worker 调用，浏览器读取、刷新和人工保存不触发模型。

`owner_scope` 为 `revenueops:` 加已认证用户名的 SHA-256，始终由后端生成。客户端的账户字段、证据对象、目标 URL 或自定义查询参数均拒绝；浏览器不持有服务密钥。站主旧记录使用独立的 `station` 作用域，商家不能读取。所有查询、修改、任务重试和采纳都检查同一作用域；跨账户 UUID 碰撞只返回冲突，不复用他人记录。

保存时 RevenueOps 重新读取该账户报告，研究服务验证白名单结构和证据哈希。变化后拒绝旧快照。UUID 绑定输入，任务与队列事务提交；有效模型结果通过原回执复用。AI 仅解释证据，订单金额不被补成收入/利润或广告效果，行业相关性不构成因果证据。

## 配置

RevenueOps 后端（忽略环境文件或部署平台的秘密配置）：

```dotenv
RESEARCH_SERVICE_URL=https://your-research-api.example
RESEARCH_SERVICE_KEY=<independent-random-key-at-least-32-characters>
```

研究站后端：

```dotenv
REVENUEOPS_SERVICE_KEY=<the-same-independent-key>
```

仅本机测试允许 `http://127.0.0.1:<port>`，其他地址必须 HTTPS。连接拒绝 URL 凭据、其他路径、查询、片段和重定向；直接连接固定服务，不继承 HTTP 代理。此密钥允许受信任的 RevenueOps 后端按账户访问复盘，不能复用模型或旧只读报告密钥，不能填入任何 `NEXT_PUBLIC_*` 变量。

前端公开配置：

```dotenv
NEXT_PUBLIC_REVENUEOPS_API_URL=https://your-revenueops-api.example
NEXT_PUBLIC_RESEARCH_SITE_URL=https://your-public-research-site.example
```

使用个人会员模型时，研究站默认拒绝所有商家调用。仅为站主本机本人设置 `REVENUEOPS_MEMBER_OWNER=revenueops:<本人用户名的SHA-256>` 才开放该账户，不向其他商家共享会员。商业模型服务、成本与隐私确认需要在公开 AI 服务前独立完成。API Key 模式继续使用原全局调用预算，每个商家每天最多新建 20 个解读任务；重试仍受全局预算和回执恢复规则约束。

## 数据生命周期

复盘与采纳检查保留至用户逐条删除；列表展示最近 30 条。完整 AI 任务沿用七天清理规则，调用回执可能包含模型回答并长期保留，不随复盘删除。删除复盘同时清理关联解读任务，不能撤回已发送的模型请求，不影响源订单。界面在主动生成和删除前展示相应说明。真实商家自助发布前仍需明确正式保留策略与账户删除流程。

## 验收

### 发布前只读检查

`/reviews` 先读取连接与当前账户权限，再开放新建复盘；连接未就绪时提供重试和数据页入口。未能读取历史不被显示成「没有记录」，重试不清空正在填写的判断或观察。模型权限由研究后端按账户计算；看到连接成功不代表模型已被调用或商业模型服务已验收。

在目标 RevenueOps API 的真实账户会话下运行：

```bash
python scripts/check_research_integration.py --base-url https://your-revenueops-api.example
```

命令从进程环境 `REVENUEOPS_CHECK_TOKEN` 读取原有登录 Bearer 会话。只通过本地忽略环境文件或秘密配置注入，不能提交、放进命令参数或 `NEXT_PUBLIC_*`。输出不包含会话、商家标识、订单金额或复盘内容。检查仅发送三个 GET：健康、当前账户复盘概览、服务器重新核对的报告；不生成模型任务、不保存快照、不同步店铺、不修改订单。公网仅允许 HTTPS，本机仅允许明确的 `127.0.0.1` 端口，拒绝重定向。

退出码 0 表示这条账户的只读链路和订单报告就绪，`ai_access` 单独说明是否开放主动 AI。无数据、旧接口、不正确会话、未连接服务均返回非零；不能用 `/health` 的 200 代替此检查。它不验证模型授权持续有效、额度、生产备份或其他账户隔离，这些仍需独立验收。
