# Co-pilot 有界证据核验（2026-10-07）

## 改进前后

之前：分析返回结构化发现后直接生成策略，证据解析与来源核对主要用于事后质量评分。JSON 解析失败可用工具摘要生成保底诊断并继续。
现在：`fetch_data → analyze → verify → recommend`。数字或字符串必须与当前成功工具的同一份返回数据中指定路径的值一致；每条发现必须有标题和非空证据。格式、来源、路径或值错误只允许重新分析一次，且不重新获取数据、不增加权限。再次失败清空发现并停止，不交付未验证诊断或行动草案。

## 停止条件与成本

- 数据查询失败：停止，不进入分析或建议模型调用。
- 明确数据不足：停止，不进行修正，不生成策略。
- 模型调用异常：停止，不自动重试，不返回原始异常细节。
- 正确诊断：直接进入建议，不增加模型调用。
- 可修正的诊断：最多增加一次分析调用；完整经营链路通常至多四次模型调用（路由、两次分析、建议），不是无限循环。
- 公共知识定义问题保留原文检索路径，不调用模型。

`verification` 返回状态及分析次数；脱敏运行日志记录同样的字段，不记录修正前的原始错误诊断。
登录、账户归属和共享配额保留。配额限制的是问答请求，不是美元支出的硬上限；新增一次修正有条件增加 token 成本。

## 验收边界

使用合成数据和脚本化模型响应，覆盖正确引用、错误数字修正、格式修正、伪造来源、错误路径、负下标、布尔/非有限数值、重复失败、缺失数据、模型异常、直接绕过建议节点，以及 HTTP 答复不泄漏未验证发现。
这些检查证明流程和引用可追溯性，不证明模型对业务含义的解释必然正确。正确数字仍可能被写进错误标题；政策适用性、因果判断和建议效果仍需人工/专门评估。不会自动发送邮件、执行营销、增加预算或迁移数据库。
本次实现与合成验收保存在本地，未包含 GitHub 推送或线上部署。
