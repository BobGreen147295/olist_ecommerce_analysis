# AI 问答安全与数据库就绪修复

范围：修复代码与本地验证，不包含 GitHub 推送、线上部署、生产迁移、套餐调整或停库。

## 已实现

1. `/v1/chat` 校验真实登录会话，未登录、伪造、过期、撤销均拒绝；认证或额度存储异常不调用模型。
2. 会话账户经 Agent 状态传入数据工具；模型返回的 owner 不被采纳；工具缺少账户时不读取数据。
3. 数据库事务额度：账户每分钟 3 次、每日 20 次，全服务每日 100 次；UTC 固定窗口，拒绝时不扣其他额度，模型失败仍计次。
4. 云模型输出、请求超时和自动重试受限；前端携带 Bearer，区分 401/429，切换会话不沿用历史，服务失败不输出演示建议作为真实回答。
5. `/health` 保持进程存活检查；新增 `/readyz` 只读数据库可达性检查，失败返回 503，限制 PostgreSQL 连接与查询等待，不暴露连接信息。
6. 迁移补齐申请与额度表；目标路由覆盖并恢复环境；全表预检、事务复制、行数与内容指纹核对，以及 `--verify-only` 只读模式。

2026-10-06 本地检查结果：后端 unittest 25 项通过；原有业务脚本 12 项通过；前端处理函数/页面测试 16 项通过；`npm run build`（含 TypeScript）与 `npm run lint` 均通过。完整 lint 中的原有匿名测试组件已仅补名称，未移除或跳过测试。此前测试发现 Windows 下测试连接未关闭，已显式关闭并复验。

本地 HTTP 测试、合成多账户数据、并发额度测试、前端真实处理函数测试覆盖上述行为；未使用真实商家数据或付费模型。迁移测试使用 SQLite 支持的 PostgreSQL 驱动替身，不代表真实 PostgreSQL 已迁移或线上已经生效。健康检查的 SELECT 1 不等于全业务表完整，也不等于模型和 Shopify 可用。
